# MarginLab — Full Code, Product & Change Review

**Date:** 2026-07-14
**Method:** Read-only audit across engine, selectors, UI, config, security, performance, and tests. Baseline: `svelte-check` 0 errors / 0 warnings; `npm run build` succeeds; `npm run i18n` clean.

---

## 1. Executive product diagnosis

MarginLab is structurally a strong educational margin-risk decision studio, but it currently has **two engines running in parallel that disagree with each other**. The Simulator/Scenarios path (`account/collateralEngine.ts` → selectors) reads from the user-editable `settings.accountProfiles`; the Portfolio/Overview/DecisionStrip path (`AccountEngine` → `portfolioStats`) reads from `app.portfolio.account` and the static `defaults.json` `BrokerProfile`. When a user tunes margin rates, collateral factors, or cost model in Settings, only half the screens update. This is the single highest-leverage problem to fix.

On top of that:
- The cost-model settings are **cosmetic** — `computeCosts` hardcodes all rates and ignores `settings.costModel`.
- `classifyRisk` has a **unit bug** that silently breaks the margin-call buffer setting for any non-zero value.
- The "Flat" scenario is **silently a -3%/day crash** because of a `-0.03` fallback injected when `dailyDrop === 0`.
- The Resilience Map's "add $X cash / reduce 1 lot" recommendations are **heuristic, not engine-backed** (`trade * 0.25`).
- Portfolio inputs allow **negative shares/price** to corrupt every downstream calculation.
- **Zero tests can run** — vitest config is missing the `$lib` alias and svelte plugin.
- The app is XSS-clean (no `@html`, no `eval`, no external links) and has sound disclaimers; the security gaps are in **unvalidated localStorage/hash hydration** that can produce NaN financial results.

The product's direction (decision studio, resilience map, scenario stories) is right. The work now is **reliability and reconciliation**, not more UI.

## 2. Page-by-page and component-by-component audit

- **Decision:** Reduce concentration / add cash / run scenarios / open finder.
- **Current UX issue:** Status classification + next-action thresholds hardcode 0.4/0.1/1.6 — domain rules in the view. No empty state when `holdings.length === 0` (shows fmtMoney(0) and "—"). Uses `app.portfolio.account` (Source A) so it ignores settings edits.
- **Priority / disposition:** **P1 / Redesign** (logic extraction + empty state + single source).

### Portfolio (`routes/portfolio/+page.svelte`)
- **User goal:** Edit holdings, cash, account params; import/export; watchlist.

## 3. Current user journey and broken decision points

The intended journey is: **"Can I open this trade?" → "How is it supported?" → "What breaks it and what can I do?"**

Broken decision points:

1. **Settings → Portfolio disagreement:** User sets initial margin to 60% in Settings → Simulator uses 60%, Portfolio/Overview/DecisionStrip still use 50%. User cannot trust any single number.
2. **Cost model → Simulator disagreement:** User tunes commission/spread in Settings → Simulator cost breakdown ignores it. User believes they tuned their broker costs; they didn't.
3. **Early-warning → Scenarios disagreement:** User sets early-warning buffer to 20% for the active profile → scenario cards still classify with the hardcoded 10%.
4. **"Flat" scenario lies:** User opens the "Flat" scenario expecting price-stay-put → sees a declining buffer timeline (because `-0.03` is injected).
5. **Margin-call buffer setting is broken:** User sets margin-call buffer to 5% → `classifyRisk` compares `bufferPct <= 0.05` (instead of `<= 5`) → margin call only triggers at 0.05% buffer, effectively never.
6. **Resilience Map "add $X" is approximate:** User reads "add $12.50 cash to cross the threshold" — that's `trade * 0.25`, not a real engine recomputation.
7. **DecisionStrip "Margin buffer 75%" is constant:** User glances at the always-visible strip and thinks they have a 75% cushion to margin call, regardless of leverage.
8. **Portfolio negative inputs:** User types `-5` shares → every calculation corrupts silently.

## 4. Feature inventory

### Keep
- LanguageMenu, Modal, ChartCard, GuidedToggle, RangeSlider (with fixes)
- Scenario projection engine (`account/scenarioEngine.ts`), trade-impact selector, margin-call map selector
- `parsePortfolio` JSON import validation (whitelisted enums, fresh-object construction)
- Concept modal live-data injection pattern
- 4-layer simulator decision panel structure
- Scenario card "neden" + chart-default + table-behind-toggle pattern

### Redesign
- **DecisionStrip:** replace `marginCalc` with `selectTradeImpact`; compute real account buffer; translate "Margin buffer".
- **MarginCallMap:** replace `trade * 0.25` heuristics with a `selectCellRemediation` selector; make matrix a `<table>`; translate "Buffer".
- **Settings:** fix `setActive` to sync both profile trackers; import defaults from `defaults.ts` instead of hardcoding; add label functions for raw enums; wire cost model into `computeCosts`.
- **Portfolio:** clamp inline inputs; centralize concentration thresholds; replace `0.25` haircut with profile-derived value.
- **Overview:** extract status classification to a selector; add empty state.
- **Scenarios:** reuse `classifyRisk`; remove dead `holdingDays` state or expose it.
- **Simulator:** fix dead `#trade`/`#map` CTAs; remove dead `direction` state; replace `196`/`-0.03` magic numbers.
- **MobileDrawer:** add focus trap, Escape, focus return; translate `aria-label`.
- **Layout breakpoints:** align sidebar-hide and menu-button-show at the same width.
- **Charts:** add `<table>` fallbacks for screen readers.

### Merge
- `AccountEngine` collateral math → `account/collateralEngine.ts` (single engine).
- `marginCalc` (`margin.ts`) → `selectTradeImpact` (single selector for DecisionStrip).
- `scenarioCalc`/`ScenarioResult`/`ScenarioVerdict` → delete (dead; `account/scenarioEngine.ts` owns this).
- `AccountCollateral` (types.ts) → `CollateralState` (collateralEngine.ts) (single interface).
- `config.ts:concentrationFactor` → `collateralEngine.ts:concentrationFactor` (single function).
- `costs.ts` interest → `interestEngine.ts:totalInterest` (single source).

### Defer
- User-defined profiles (currently fixed 3-way; type change is non-trivial).
- Scenario editor UI (`scenarioEngine.definitions` is seeded but unused; wiring is a large effort).
- Stale-data indicators with real timestamps (requires a data pipeline).
- Component/E2E/a11y test suite (important but large; unblock unit tests first).

### Remove
- `app.d.ts` malformed content (replace with standard SvelteKit template).
- `layerchart` dependency (zero source imports; dead).
- Dead code: `scenarioCalc`, `ScenarioResult`, `ScenarioVerdict`, `supportSummary`, `resolveCostModel`, `resolveEarlyWarning`, `tradeInitialMargin`, `tradeMaintenanceMargin`, `AccountEngine.addTrade`, `applyScenario`, `updateCash`, `updateHolding`, `enforcePDT`, `isPTDAccount`, `direction` state, unused `ic-chevron-right`/`ic-scale` icons, unused `levelLabel` import, unused `:global(.rot)` CSS.
- `globalDefaults` writes in `simulator/setInitial`/`setMaint` (pollutes admin seed).

## 14. Risks, assumptions, and unresolved questions

1. **`AccountEngine` deletion risk:** `AccountEngine` is used by `portfolioStats`, which is used by 5+ pages. Replacing it with `selectAccountSnapshot` is a large change. **Assumption:** we can make `portfolioStats` delegate to `selectAccountSnapshot` without changing its public return shape, so consumers don't break. **Unresolved:** should `portfolioStats` be deleted in favor of `selectAccountSnapshot`, or kept as a thin wrapper?

2. **`globalDefaults` role:** The 3-tier settings design made `globalDefaults` an admin seed, but the Simulator writes to it. **Unresolved:** should `globalDefaults` be (a) removed entirely (profile is the only source), (b) kept as a non-editable seed for future profile-creation, or (c) given a real fallback role in `resolveAccountParams`?

3. **`earlyWarningBufferRate` unification:** Should the profile's value be the single source (and `scenarioEngine.riskThresholds.earlyWarningBufferRate` deleted), or vice versa? **Assumption:** profile wins (per the 3-tier design). **Unresolved:** the scenario-engine threshold also has `marginCallBufferRate` — should that move to the profile too?

4. **`bufferPct` naming:** Two concepts share the name. **Assumption:** rename the per-trade one to `priceBufferPct` and keep `bufferPct` for the account-level one. **Unresolved:** should the per-trade buffer be shown at all in the Simulator, or demoted in favor of the account-level one?

5. **`@inlang/paraglide` vulnerability:** 9 critical advisories with no fix. **Assumption:** build-time-only exposure is acceptable for an educational client-only app. **Unresolved:** should we migrate to a different i18n approach?

6. **Profile set is fixed at 3.** **Assumption:** this is intentional for an educational tool. **Unresolved:** is user-defined profiles a future requirement?

7. **`ssr=false` + no skeleton.** **Assumption:** acceptable for an SPA. **Unresolved:** should we add a minimal static shell in `app.html` to prevent CLS?

8. **URL-as-persistence privacy.** **Assumption:** the current "URL is the state" design is intentional for sharing. **Unresolved:** should we split persist (localStorage) from share (explicit button)? **Resolved:** persistence moved to `mc-app-state` localStorage (`syncStorage` 250ms debounced); URL sharing made explicit via Topbar Share button (`buildShareUrl()` + clipboard, fallback `prompt()`).
